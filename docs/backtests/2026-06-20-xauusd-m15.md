## Findings

### Daily limit can overshoot

The configured daily closed-loss limit was approximately USD 105-108 during the
test. Protection activated with losses as high as USD 155.52 because the current
implementation checks the limit after a trade closes. Before placing a new order,
the EA should also require:

```text
current closed loss + proposed trade risk <= daily loss limit
```

This is required if 1% is intended as a hard daily loss ceiling.

### Invalid setups are retried

The EA logged 1,277 local validation rejections. When price has already crossed
the calculated retracement before order placement, the same swing is reconsidered
on later M15 bars. Such a swing should normally be recorded as skipped, and the
log should state the precise rejection reason.

### Minimum-volume skips are material

One hundred setups could not use the broker's minimum volume without exceeding
the 0.5% risk allowance. Skipping these trades is correct risk behavior, but the
frequency should be monitored across brokers with different XAUUSD contracts.

## Assessment

The implementation completed the test without runtime or broker execution errors,
and the strategy was profitable in this sample. However, a profit factor of 1.15,
a recovery factor below 1.0, dependence on one profitable month, and a losing buy
side mean the evidence is not sufficient for live trading.

The next code revision should address the daily-risk pre-check and skipped-swing
tracking. After that, rerun this exact period for regression comparison, then test
multiple years and conduct a demo forward test. Live commission, swap, latency,
and execution differences must also be considered because this report charged no
commission or swap.
